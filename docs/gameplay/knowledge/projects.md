# Projects across turns

A player records when their character starts a project, such as an investigation. The note can include costs and other related details.

Sometimes the game master gives an estimate of how long the work will take. If the player gets an estimate, they record it. A project can also start without an estimate.

## How the game master runs a project

- The game master sets the cost. A project can cost one sum at the start, an amount every round, or both. An amount every round settles like other payments.
- The game master decides whether the project needs skill checks and whether it has setbacks.
- The game master may give a progress update during a later turn. The player can also ask for an update.
- The game master decides when the project ends. This can occur in the interterm or during a player's turn.

## How players keep project notes

Players keep ordinary documents. Some use one document per project, or group related documents in a project folder.

One player's notes collection has three main documents:

- `Character.md` contains the character and contacts.
- `Campaign.md` contains money, a dated timeline, and sections for ongoing projects.
- `Research.md` contains research grouped by topic.

For example, the campaign timeline records when wireless technology research started. A separate project section contains related plans. A project can therefore appear in several sections of the same document.

Players use wording to distinguish plans from completed actions.

## Older notes and current state

When notes conflict, the later dated update is the current state. An older project section may remain unchanged after progress occurs.

For example, the campaign timeline records the construction of a Class 100 clean room. An older project section still says the character needs one. The player forgot to update the older section.
